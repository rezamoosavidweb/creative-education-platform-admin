## Audit Findings

Existing API layer:
- `src/lib/api/schema.d.ts` is generated by `openapi-typescript` and provides
  paths, operations, schemas, request bodies, responses, and response headers.
- There is no generated runtime API method layer today. No app source imports
  `src/lib/api/schema.d.ts` yet.
- `src/lib/handle-server-error.ts` handles only basic axios error to toast
  mapping. `VITE_API_URL` exists in `.env.example` but is not used.

Generated SDK:
- Current admin output is type-only, not a callable SDK.
- Backend also commits `../api/src/generated/openapi-types.ts`; backend
  generation is via `pnpm generate:contracts`.
- Increment 0.1 must inspect the generated output before adding runtime SDK
  tooling. If a generator adds API methods, those generated methods are the only
  method source.

Auth store:
- `src/stores/auth-store.ts` stores a mock access token under
  `thisisjustarandomstring`.
- `src/features/auth/sign-in/components/user-auth-form.tsx` uses `sleep`,
  `mock-access-token`, and a mock user shape.
- `src/components/sign-out-dialog.tsx` only clears local state.

React Query:
- `QueryClient` is created inline in `src/main.tsx`.
- Global 401 handling resets auth and redirects, but refresh rotation is absent.
- Only dashboard uses React Query today, and its service returns generated mock
  data.

Router guards:
- `src/routes/_authenticated/route.tsx` renders `AuthenticatedLayout` without an
  auth guard.
- No route metadata or `requiredCapabilities` exists yet.

Reusable components:
- Layout shell, sidebar, header, command menu, profile dropdown, dialogs, cards,
  status pills, and shadcn primitives are already present.
- Sidebar data is shared by `AppSidebar`, `Header` breadcrumb resolution, and
  `CommandMenu`.

DataTable:
- `src/components/data-table/*` contains the shared toolbar, pagination, column
  header, faceted filter, view options, and bulk actions.
- `src/hooks/use-table-url-state.ts` already syncs page, page size, global
  filter, and column filters to route search params.
- Current table usage is client-side. Server pagination/sorting/filtering should
  be added as adapters around the existing table pattern.

Forms:
- Forms consistently use `react-hook-form`, zod, and shadcn `Form` primitives.
- `SelectDropdown`, `PasswordInput`, `ConfirmDialog`, dialogs, and sheets should
  be reused.
- Current write flows mostly call `showSubmittedData` or local mock handlers.

Backend auth/capability contract:
- Login returns `LoginPayloadDto` with `user`, `accessToken`, and
  `refreshToken`.
- Refresh accepts `RefreshTokenDto` and returns a rotated access/refresh pair.
  Backend revokes the presented refresh token and treats reuse as unauthorized.
- Logout revokes all active refresh tokens for the current user.
- Active sessions are exposed at `GET /auth/sessions` and revoked by
  `DELETE /auth/sessions/{id}`.
- Current capabilities are exposed at `GET /identity/me/capabilities`.
- Current organizations are available through `GET /organizations/mine`.

## KEEP

- Keep the existing React/Vite/TanStack Router/TanStack Query/Zustand stack.
- Keep the Enterprise Admin layout and shadcn component system.
- Keep `components/layout/*`; make it capability-aware without redesigning it.
- Keep `components/data-table/*` and `use-table-url-state`; adapt for server
  pagination and cursors.
- Keep the RHF + zod + shadcn form pattern and shared form controls.
- Keep `handleServerError` as a starting point, expanding it through the central
  API infrastructure.
- Keep `.env.example`'s `VITE_API_URL` base URL convention.

## REMOVE

Remove later, only as each replacement lands:
- Mock auth token/user/session behavior.
- Mock dashboard service/data once real endpoints are wired.
- Template-only mock data/types for backend-owned entities.
- Static sidebar user/team values once current user/org data is available.
- `showSubmittedData` submit flows in API-backed forms.
- Duplicate role/permission assumptions that conflict with backend
  capabilities.

No source code was removed in Increment 0.0.

## REFACTOR

- Refactor auth state to store backend token payloads, current user, current org
  selection, and restore status from generated DTOs.
- Move API concerns out of pages and feature components into generated SDK,
  infrastructure, and hooks.
- Extract or centralize query-client setup if needed for auth refresh and tests.
- Add route `requiredCapabilities` metadata and keep `beforeLoad` small.
- Filter sidebar, command menu, buttons, and row actions through one
  `CapabilityGate`/capability helper.
- Add table adapters for offset pagination, cursor pagination,
  `X-Next-Cursor`, server sorting, and server filtering without forking
  DataTable.
- Add form helpers for API validation mapping, submit state, server errors, and
  generated enum/select options.

## NEW

Create only with real usage:
- One generated OpenAPI SDK/contract output that owns DTOs, enums, requests,
  responses, API methods, and available error types.
- One API infrastructure layer for axios, interceptors, refresh rotation,
  retries, cancellation, uploads, downloads, idempotency keys, next-cursor
  headers, and global error mapping.
- Auth hooks: current user, current organization, capabilities, session restore,
  sessions, revoke session, login, logout, refresh.
- `CapabilityGate` as the standard authorization primitive for pages, menus,
  buttons, and actions.
- Reusable React Query hooks only when immediately consumed.
- DataTable and form adapters only when used by the first API-backed surface.
